# Граница: где модель, где код

## Модель дёргается ровно 6 мест

| # | Слот | Вход → Выход | Почему не код | Контракт |
|---|---|---|---|---|
| 1 | Parse | сообщение → `TripRequest`-delta (поля + `hard|soft` + `known|unknown|inferred|defaulted` + `source`) | естественный язык, 20+ полей | Pydantic + Instructor, retry с feedback → fallback-парсер |
| 2 | Question | посчитанный кодом список «что добить» → ≤2 формулировки | нужна формулировка, не решение | schema `{field, text, options[], allow_skip}` |
| 3 | Soft relevance | `indexed_text` отеля + фразы предпочтений → 0..1 | «атмосферный» не выражается полем | **не LLM по возможности** → cross-encoder / JEV (см. ниже) |
| 4 | Finalists | 12 проффильтрованных кандидатов + веса → 3 + причина | выбор между почти равными | schema `{picked[], rationale[]}` |
| 5 | Explain | `TripState` → текст карточки | текст | числа строго из state, пост-сверка guard'ом |
| 6 | Diff | новое сообщение → какие поля задело | язык | enum-словарь полей, не свободный вывод |

Бюджет на один ход: ≤6 LLM-вызовов, ≤12 tool-вызовов, ≤20 с wall-clock, ≤2 вопроса,
≤2 итерации repair. Лимит кончается → не ошибка, а «лучшее из найденного + что не
подтверждено».

## Модель — излишество (дорого, медленно, и невоспроизводимо)

| Задача | Чем решается |
|---|---|
| хватает ли данных искать | код: unknown × значимость × вероятность изменить результат; с 28-го — ещё и «поиск сам показал расходимость» |
| какие сервисы звать | реверс-индекс реестра `поле → инструмент` |
| строить запрос к эмбеддингам | код: `" ".join(soft values)` |
| фильтровать по бюджету/датам/гостям | SQL |
| ранжировать | Python-формула, нормализованные признаки, объяснимые веса |
| стыковки и сумма | `datetime`-арифметика + `Decimal` |
| **ревью корректности требований** | **только код.** Review-модель пропустит превышение бюджета на 8% — и это провал на защите |
| выбор repair-действия | маппинг `Violation.code → действие` + дедуп подписей |
| пересчёт валют | `Decimal` |

## Слот решений (DecisionProvider)

```python
class DecisionProvider(Protocol):
    def decide(self, state: TripState, questions: list[Question]) -> list[Decision]
    # Decision = (option, probability, needs_confirmation)
```

Это единственное место архитектуры, где бэкенд решений съёмный:

| Бэкенд | Роль | Статус |
|---|---|---|
| `ThresholdProvider` | детерминированный порог по значимости unknown-полей | **дефолт, работает офлайн** |
| `AskAfterSweepProvider` | ищи с безопасным дефолтом; спрашивай, если `CANDIDATES_EMPTY` / разброс кандидатов > порога / hard-конфликт | основная стратегия: вопрос после замера, а не до — этого требует и задание |
| `RerankProvider` | cross-encoder для мягкой релевантности | дешевле и предсказуемее LLM-скоринга |
| `JEVProvider` | typed-решения с калиброванной вероятностью, пачка вопросов за один вызов | optional, **не в критическом пути демо** |
| `LocalLLMProvider` | локальная модель для diff-классификации и офлайн-фолбэка парсинга | фолбэк при недоступности внешней |

Вероятность, а не только выбор, нужна ровно для одного правила: `p < 0.6 → не подставлять
дефолт, а спросить`. То же ложится на статусы `verified / partially_verified / unknown`.
Альтернатива без отдельной модели — калибровка по logprobs на eval-наборе.

Что бэкенд решений **не** делает: не выбирает инструменты. Там точный реверс-индекс
зависимостей, и вероятности в этом месте испортили бы воспроизводимость трейса.

## Сравнение бэкендов на eval-наборе

Один прогон 12 сценариев на каждом бэкенде, таблица в `evaluation/backends.md`: точность
извлечения, доля валидных схем, p95 latency, стоимость полного цикла. Это то, что
превращает «мы взяли JEV/reranker/порог» в измеренный выбор.

## Антигаллюцинационный guard

Финальный текст прогоняется regex'ом: все числа (цены, °C, часы, количество гостей)
сверяются с `TripState`. Расхождение → перегенерация с указанием конкретного числа,
после второй неудачи → шаблонная строка из state. ~40 строк, и это единственный
механизм, который реально мешает модели написать «152 000 ₽» вместо посчитанных
148 900 ₽. На защите показывается намеренно.
