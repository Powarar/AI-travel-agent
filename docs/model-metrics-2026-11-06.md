# Измерения моделей — 6 ноября 2026

## Что подключено

- Каждый новый model span содержит оценку стоимости, версию тарифов и статус
  полноты расчёта. Старые spans переоцениваются отдельно и помечаются как historical.
- `/v1/monitoring/models` показывает стоимость HTTP-вызовов и связанные parse eval.
- `/v1/monitoring/accuracy` показывает последние результаты по dataset hash,
  модели, версии промпта и режиму live/offline.
- `evaluation_runs` хранит неизменённые исходные отчёты. Публичная сводка вычисляет
  метрики из per-case checks функцией `parse_accuracy_summary`, определение
  `parse-field-v2`: числитель и знаменатель ожидаемых полей не смешиваются с
  проверками отсутствия полей. В раннем исходном JSON `correct_fields` называл
  количество всех верных assertions; это имя исправлено для новых отчётов и API.

Единственная ошибка — `party.adults` в кейсе `budget_direct` («Бюджет 150к на двоих,

Первый запуск из окружения хоста получил 20 сетевых ConnectTimeout и использовал

effective accuracy — 0. Это показатель недоступности основного пути в том запуске,
а не доказательство нулевого качества модели. Из Docker тот же датасет выполнился
без fallback. Конкретная первопричина различий сетевого доступа не установлена.

## Как считается цена

Тарифы взяты из таблицы пользователя, а не объявлены текущим официальным прайсом:

| Модель | Вход, ₽/1M | Выход, ₽/1M |
| --- | ---: | ---: |
| deepseek-v4.1-flash-1017 | 30 | 120 |
| qwen3.7-plus | 64 | 256 |
| qwen3-embedding-8b | 2 за reported total tokens | — |
| qwen3-reranker-8b | не задан | не задан |
| rerank-3-lite | не задан | не задан |

1000 input + 100 output токенов DeepSeek дают
`1000×30/1_000_000 + 100×120/1_000_000 = 0,042 ₽`.
Вычисления используют Decimal без округления до копейки каждого вызова.
Нельзя округлять 0,000014 ₽ embedding-вызова до нуля и затем складывать нули.

`known_estimated_cost_rub` — только известный subtotal. `unpriced_calls` и
`cost_coverage` показывают пропуски. Неизвестный тариф reranker и отсутствующий
usage не считаются бесплатными запросами. Статусы неуспеха не доказывают отсутствие
списания у провайдера. Для настоящего биллинга нужна сверка с его ledger/invoice.

HTTP telemetry, отдельный eval и фоновая индексация — разные области учёта.
Сумма на `/monitoring/models` не является полной стоимостью проекта.

## Чего эти измерения не доказывают

Нет отдельного holdout большого размера, доверительных интервалов, relevance-разметки
для nDCG@3, измеренной factuality финального ответа и сверки с invoice. Успешный HTTP
и валидный JSON не равны accuracy. Среднее по всему диалогу не заменяет метрики
каждого слота. Число 97,297% относится именно к этому небольшому датасету.
