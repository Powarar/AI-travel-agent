# Доска задач

Два человека. Финальные сборки принимают до **2026-10-29 10:00 UTC+3** — после этого часа код
уже не меняется, только зашита. От счёта на 2026-10-25 остаётся ~97 ч календарных, то есть
4 дня × 8 ч ≈ 32 ч рабочих рук на человека. Задача = тикет: владелец, волна, зависимости,
текст для вставки агенту, приёмка командами.

## Как пользоваться

1. Открыть волну, взять **свой** блок, у которого все «зависит» уже в `done`.
2. В чат агенту: `services/agent/docs/INFA.md` целиком + текст из поля «Текст для вставки» одного блока +
   `services/agent/docs/CONTRACTS.md`. Больше ничего; `docs/ARCHITECTURE.md` — только раздел, названный в
   блоке. Агент не инициирует чтение остальных документов.
3. Прогнать команды из поля «Приёмка». Не сходится — блок не закрывать.
4. Коммит: только файлы из поля «Файлы». Если задет контракт — `services/agent/docs/CONTRACTS.md` в этом же
   коммите.
5. Пересечение с чужим треком — вопрос в общем чате, не правка чужих файлов.

## Как чекать вывод агента

Пять проверок, в этом порядке. Первые две отклоняют большинство плохих прогонов.

1. `git diff --stat` — изменены только файлы из поля «Файлы» и, если задет контракт,
   `services/agent/docs/CONTRACTS.md`. Всё остальное в диффе — отклонить, не «починить потом».
2. Прогнать приёмку самому: `pytest`, `mypy`, grep из блока. Слова агента о том, что тесты
   зелёные, не считаются результатом.
3. Если в диффе есть `services/agent/docs/CONTRACTS.md` — читать его первым: имя поля, код нарушения или
   SSE-событие могли быть подменены под удобную реализацию.
4. Ищем запрещённое: импорты LLM-пакетов в `validation/`, `float` или «рубли в `int`» в
   money-коде, `httpx`/`requests`/парсеры вне `ingestion/`, новая зависимость в
   `pyproject.toml` без явного решения в блоке.
5. Прочитать логику (не форматирование) одного самого опасного файла в прогоне: для T-03 это
   границы стыковок, для T-05 — policy-рёбра и обрыв по лимиту, для T-08 — что именно
   считается `kept_components`.

| Роль | Зона |
|---|---|
| П1 | агентский трек: модели, граф, валидатор, repair, LLM-слоты, грейдеры и метрики |

Критический путь: T-01 → T-03 → T-04 → T-05. Всё, что вне его, выкидывается без сожаления.

**Нагрузка, честно.** П1: T-01 3ч, T-03 4ч, T-04 3ч, T-05 6ч, T-07 5ч, T-08 5ч, T-09 4ч ≈
30 ч при ~32 ч реальных рабочих часов до фриса. П2: T-11 3ч, T-02 5ч, T-06 5ч, T-10 4ч, T-12 8ч,
сценарии 2ч ≈ 27 ч. Запаса почти нет, поэтому T-13 по умолчанию не начинается, а векторная
часть T-10 подключается после зелёного T-05, а не до: гейту хватает SQL-фильтра.

**Правило выгрузки.** Если к вечеру дня 2 `T-05` не зелёный — T-10 сворачивается до одного
SQL-фильтра без векторов, T-09 сокращается до 6 сценариев, T-13 не начинается вообще, силы
идут в золотой путь. Это не поражение: за неидеальный ранжирователь очки не снимают, а демо
без сквозного сценария не показывается.
